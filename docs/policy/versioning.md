# 버전 정책 (초안)

> **이 문서는 초안이다.** 표시한 모든 수치(기간·개수·횟수)는 **제안**이며 확정이 아니다.
> 사용자가 확정하기 전까지 `terra-sdk`는 이 정책을 약속으로 광고하지 않는다.
> **[제안]** 표시가 없는 항목은 구조 설명이거나 설계 문서에서 이미 정해진 사실이다.

## 1. 무엇에 버전을 붙이나

| 대상 | 규칙 |
| --- | --- |
| Go 모듈 | 단일 모듈 `github.com/StellaxiaLab/terra-sdk` 하나의 버전 (설계 P-2). 하위 패키지(`modulesdk` · `modulert` · `svi` · `protocol` · `conformance`)는 따로 버전을 갖지 않는다 |
| 태그 | `vMAJOR.MINOR.PATCH`. Go 모듈 규약상 태그가 곧 릴리스다 |
| 와이어 계약 | 환경변수 6 · 헤더 1 · 경로 2와 그 JSON 모양([[docs/contracts/module-host-http-contract]]). Go API와 **별개로** 더 엄격하게 다룬다(§3) |
| 적합성 키트 | SDK와 같은 버전을 쓴다. 규칙이 늘어나면 §5를 따른다 |

## 2. semver

[Semantic Versioning 2.0.0](https://semver.org/lang/ko/)을 따른다.

| 올리는 자리 | 언제 |
| --- | --- |
| PATCH | 공개 API·와이어 계약이 그대로인 버그 수정, 문서 |
| MINOR | 하위 호환 기능 추가(새 심볼, 새 선택 경로) |
| MAJOR | 하위 호환을 깨는 변경 |

v0.x에서는 semver 규약대로 MINOR에서도 Go API가 깨질 수 있다. 깨짐의 범위는 §3이 정한다.

## 3. v0.x 동안 깨짐 허용 범위

| 영역 | v0.x에서 | 비고 |
| --- | --- | --- |
| Go 공개 심볼의 이름·시그니처 | **MINOR에서 깨짐 허용 [제안]**, PATCH에서는 불가 | 깨는 MINOR는 릴리스 노트 맨 위에 "깨짐"으로 적는다 **[제안]** |
| 와이어 계약(환경변수명 · 헤더명 · 경로 · JSON 필드명과 의미) | **추가만 허용, 변경·삭제 불가 [제안]** | 이미 배포된 모듈은 다시 빌드할 수 없다. 계약 변경은 사용자 결정 사항이다(설계 §6 규칙 3) |
| 상수 값(`DelegatedCredentialPrefix` 등 와이어에 나가는 값) | 와이어 계약과 같게 취급 | |
| `conformance` 키트의 API | MINOR에서 깨짐 허용 **[제안]** | |
| `modulert`의 호스트 쪽 보조(`Activate` 등, 설계 §7 N-1) | MINOR에서 깨짐 허용 **[제안]**, 제거될 수 있음 | 모듈이 의존할 대상이 아니다 |

## 4. 폐기

1. 폐기할 심볼에 `// Deprecated: <대체 방법>` 주석을 단다.
2. **폐기 후 최소 2개 MINOR 릴리스 또는 90일 중 긴 쪽을 유지한 뒤 제거한다 [제안]** (v1 이후).
3. v0.x에서는 **최소 1개 MINOR 릴리스 또는 30일 [제안]**.
4. 와이어 계약의 항목은 v0.x·v1 모두 폐기하더라도 **제거하지 않는다**. 호스트가 계속 받아 주는 기간을 별도로 정해야 하며 이 초안은 정하지 않는다(미결정).

## 5. 적합성 키트의 규칙 추가

새 규칙은 이미 통과하던 모듈을 실패시킬 수 있다. **새 규칙은 한 MINOR 동안 경고로만 내고 다음 MINOR에서 실패로 올린다 [제안].** 키트에 경고 수준이 아직 없으므로(현재는 PASS/FAIL뿐) 이 규칙을 지키려면 키트 확장이 필요하다 — 미구현.

## 6. 호스트와 모듈의 호환

- 호스트(Terra)는 `terra-sdk`를 `type X = sdk.X`로 소비한다(설계 D-3). 호스트가 SDK를 올리면 모듈이 쓰는 와이어 계약이 같이 움직이므로 §3의 와이어 규칙이 호환성의 실질적 보증이다.
- **호스트는 같은 MAJOR 안에서, v0.x에서는 직전 2개 MINOR 안에서 빌드된 모듈을 받아 주는 것을 목표로 한다 [제안].** 와이어 계약이 추가만 허용되므로 이 목표는 계약 규칙에서 따라 나온다.
- 와이어 계약에 버전 표지가 **없다**(핸드셰이크 응답에도 환경변수에도). 계약 버전을 모듈이 선언하게 할지는 미결정이다(설계 §8의 "코어 버전 범위 필드(`compatibility`)"와 같은 결을 가지므로 1단계 범위 밖이다).

## 7. v1.0 조건 (제안)

다음이 모두 충족되면 v1.0을 낼 수 있다 **[제안]**:

1. Terra와 `modules`가 모두 태그 버전으로 소비하고 있다 (replace 없이).
2. 연속 2개 MINOR 동안 와이어 계약과 `modulesdk` 공개 API의 깨짐이 없었다.
3. 적합성 키트가 §5의 경고 수준을 갖췄다.
4. 라이선스가 정해졌다(설계 P-3, 사용자 결정).

## 8. 잘못 나간 버전

잘못 나간 태그는 지우지 않고 `go.mod`의 `retract` 지시어로 철회하고 PATCH로 고친다. 태그를 지우거나 옮기지 않는다(Go 모듈 프록시 캐시와 어긋난다).

## 9. 릴리스 절차

1. 병합된 `main`에서 CI(`go build` · `go vet` · `go test -count=1 ./...`)가 통과인지 확인한다.
2. 사용자가 `vX.Y.Z` 태그를 만든다. 태그는 PR 병합 뒤 사용자가 확인하고 만든다.
3. `release` 워크플로가 같은 검증을 다시 돌리고 GitHub Release를 만든다(자동 생성 노트).
